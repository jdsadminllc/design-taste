# AI Design Anti-Patterns

A catalog of 17 visual and typographic patterns that signal "generated by AI."
The CLI scanner detects these. This document explains what they are, why they're
bad, and how to fix them.

---

## 1. Default Inter

**The pattern:** Using `Inter`, `system-ui`, or `-apple-system` as your font
stack without making a deliberate typographic choice.

```css
/* BAD — default font stack with zero intent */
body {
  font-family: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
}
```

**Why it's bad:** Inter is the default font in Figma and the most common
recommendation in AI-generated CSS. When the first font in your stack is the
one every AI model defaults to, the design reads as "nobody chose this." Type is
the single biggest signal of design intent — defaulting it communicates that
nobody cared.

**The fix:** Choose a typeface based on the subject matter. A legal document
and a children's app should not share the same font. Pick one typeface — one —
and make it the anchor of the design.

```css
/* GOOD — deliberate choice */
body {
  font-family: "Source Serif 4", Georgia, serif; /* editorial, serious */
}
```

## 2. Accent Word

**The pattern:** Italicizing or coloring a single word in a headline for
emphasis, usually the verb or a value-prop adjective.

```html
<!-- BAD -->
<h1>Build <em>better</em> products with data-driven design</h1>
```

**Why it's bad:** It's the typographic equivalent of a laugh track — telling
the reader which word to care about instead of letting the writing do the work.
It breaks the visual rhythm of the headline, draws the eye to a fragment rather
than the whole, and is almost never present in professional typography. LLMs
love it because it mimics "design flair" without understanding why a designer
would actually italicize something.

**The fix:** Write a headline that doesn't need typographic crutches. If a word
needs emphasis, rewrite the sentence so the structure carries the weight.

```html
<!-- GOOD — writing carries the emphasis, not italics -->
<h1>Build products that improve when the data disagrees with you</h1>
```

## 3. ALL CAPS Labels

**The pattern:** Setting eyebrow labels, metadata, or UI labels in all caps
with `letter-spacing: 0.05em–0.15em`.

```css
/* BAD */
.eyebrow {
  text-transform: uppercase;
  letter-spacing: 0.1em;
  font-size: 0.75rem;
  color: var(--color-text-muted);
}
```

**Why it's bad:** All-caps labels are an overused crutch. They originate from
print design where small caps had a specific job (signaling section changes in
books). In UI, they reduce legibility (capitals have less distinctive word
shapes), and when every label is tracked-out caps, the page becomes a wall of
rectangular blocks. AI models reach for this because it's the most common
pattern they've seen, not because the design calls for it.

**The fix:** Use sentence case at a legible size. If you need visual separation,
use color, weight, or a border — not caps.

```css
/* GOOD — readable, natural */
.eyebrow {
  font-size: 0.875rem;
  font-weight: 500;
  color: var(--color-text-muted);
  padding-bottom: 0.25rem;
  border-bottom: 1px solid var(--color-border);
}
```

## 4. Mono Data Labels

**The pattern:** Using a monospace font for small data labels, metrics, or
timestamps when the rest of the design is proportional.

```css
/* BAD */
.stat-value {
  font-family: "JetBrains Mono", monospace;
  font-size: 0.75rem;
}
```

**Why it's bad:** Monospace has a specific semantic: it means "this is code" or
"this is tabular data where alignment matters." When applied to a single stat
or timestamp in an otherwise proportional design, it looks like a CSS mistake —
as if the font stack fell through to the monospace fallback. AI models love this
because they associate "technical" or "data" with monospace, but in practice it
clashes.

**The fix:** Use tabular figures from your proportional font (`font-variant-numeric: tabular-nums`) if you need alignment. Otherwise, use the same typeface as the rest of the design.

```css
/* GOOD — proportional, tabular figures for alignment */
.stat-value {
  font-variant-numeric: tabular-nums;
  font-size: 0.875rem;
}
```

## 5. Tracked Out

**The pattern:** `letter-spacing` greater than 0.1em on labels above headings,
typically combined with uppercase.

```css
/* BAD */
.section-label {
  text-transform: uppercase;
  letter-spacing: 0.2em;
  font-size: 0.75rem;
}
```

**Why it's bad:** Excessive letter-spacing destroys legibility at small sizes.
At 0.2em on a 12px font, the gaps between letters are wider than the letter
strokes themselves. The result is text that the eye has to work to decode rather
than read. It's the single most reliable signal of AI-generated CSS.

**The fix:** Keep letter-spacing below 0.05em for labels, or drop it entirely.
If the label feels weak without tracking, the problem is the font weight or
color, not the spacing between letters.

```css
/* GOOD — legible, restrained */
.section-label {
  font-size: 0.8125rem;
  font-weight: 600;
  letter-spacing: 0.02em;
  color: var(--color-text-muted);
}
```

## 6. Purple Gradient

**The pattern:** A `linear-gradient` using purple-to-indigo (#7C3AED to
#4F46E5 or similar) on dark backgrounds, especially for hero sections, cards,
or CTA buttons.

```css
/* BAD */
.hero {
  background: linear-gradient(135deg, #7C3AED 0%, #4F46E5 100%);
}
```

**Why it's bad:** Purple gradients are the Comic Sans of AI-generated design.
They're heavily overrepresented in training data because they're the default
"modern tech" gradient in landing page templates. When every SaaS homepage,
every AI tool, and every Web3 project uses the same gradient, it no longer
communicates "modern" — it communicates "template."

**The fix:** If a gradient serves the brand, construct one from brand colors. If
the brand doesn't have a gradient, it doesn't need one. A single solid color
with good typography beats a purple gradient every time.

```css
/* GOOD — uses actual brand colors, or skips the gradient entirely */
.hero {
  background-color: var(--color-surface);
  /* Or, if gradient is intentional: */
  /* background: linear-gradient(135deg, var(--color-brand), var(--color-brand-dark)); */
}
```

## 7. Cream Default

**The pattern:** Using `#F4F1EA`, `#FAF7F2`, or similar warm cream/off-white
as the default background color.

```css
/* BAD */
body {
  background-color: #F4F1EA;
}
```

**Why it's bad:** Cream backgrounds are the default "warm and human" setting
that AI models reach for when they're told to make a design feel "organic" or
"approachable." The problem is that cream reads as unprinted paper — it looks
like a mistake on most screens, especially next to pure-white cards and
elements. It also performs poorly in bright environments and creates contrast
issues with standard gray text.

**The fix:** Use white (`#FFFFFF`) as the default unless there's a specific
reason not to. If you need warmth, add it through typography (a warm serif) and
imagery, not through a tinted background that fights every element placed on it.

```css
/* GOOD — neutral, lets content carry the warmth */
body {
  background-color: #FFFFFF;
  color: #1A1A1A;
}
```

## 8. Terracotta Accent

**The pattern:** Using `#D97757` or similar terracotta/clay/burnt-orange as
the accent color on cream or warm backgrounds.

```css
/* BAD */
:root {
  --accent: #D97757;
  --bg: #F4F1EA;
}

.button-primary {
  background-color: var(--accent); /* terracotta */
}
```

**Why it's bad:** Terracotta + cream is the AI's "earthy artisan brand" preset.
It's the visual equivalent of the word "bespoke." This pair is so
overrepresented in AI-generated designs that it signals the opposite of what
it's trying to achieve — instead of feeling handcrafted, it feels generated by
the same model that generated every other "artisan" brand.

**The fix:** Choose an accent color that comes from the brand, not from the
model's training distribution. If there is no brand yet, pick a color that means
something about the product or audience.

```css
/* GOOD — chosen, not defaulted */
:root {
  --accent: #1D4ED8; /* trust, stability — or whatever the brand needs */
  --bg: #FFFFFF;
}
```

## 9. Uniform Radius

**The pattern:** Applying the same `border-radius` to every element regardless
of its size or hierarchy.

```css
/* BAD */
.card    { border-radius: 8px; }
.button  { border-radius: 8px; }
.input   { border-radius: 8px; }
.avatar  { border-radius: 8px; }
.modal   { border-radius: 8px; }
.tag     { border-radius: 8px; }
```

**Why it's bad:** Radius should scale with element size — a small tag needs a
tighter radius than a large modal. Uniform radius flattens the visual hierarchy
and makes every element feel like it came from the same stamp. It's an
AI-generated shortcut that skips the spatial reasoning a designer applies.

**The fix:** Scale border-radius proportionally. Small elements get 2–4px,
medium get 6–8px, large get 12–16px. Round avatars or pills get fully rounded
corners.

```css
/* GOOD — radius scales with element size */
.tag     { border-radius: 4px; }
.button  { border-radius: 6px; }
.card    { border-radius: 8px; }
.modal   { border-radius: 12px; }
.avatar  { border-radius: 50%; }  /* or 9999px */
```

## 10. Clone Shadows

**The pattern:** Applying an identical `box-shadow` to every card on the page.

```css
/* BAD */
.card {
  box-shadow: 0 4px 6px -1px rgb(0 0 0 / 0.1);
}
```

**Why it's bad:** Cards at different levels of hierarchy should cast different
shadows. A card that sits on the page surface should have a subtle shadow; a
card that floats above others (like a modal or dropdown) should cast a deeper
shadow. Clone shadows make the page feel flat and templated — they say "I copied
this value from somewhere and pasted it everywhere."

**The fix:** Build a shadow scale. Shallow shadows for surface-level cards,
medium for elevated cards, deep for modals and overlays.

```css
/* GOOD — shadow scale */
:root {
  --shadow-sm:  0 1px 2px 0 rgb(0 0 0 / 0.05);
  --shadow-md:  0 4px 6px -1px rgb(0 0 0 / 0.1);
  --shadow-lg:  0 10px 15px -3px rgb(0 0 0 / 0.1);
  --shadow-xl:  0 20px 25px -5px rgb(0 0 0 / 0.1);
}

.card-static  { box-shadow: var(--shadow-sm); }
.card-elevated { box-shadow: var(--shadow-md); }
.modal         { box-shadow: var(--shadow-xl); }
```

## 11. Card Nesting

**The pattern:** Cards inside cards inside cards — a three-level-deep nesting
of bordered/rounded containers.

```html
<!-- BAD -->
<div class="card"><!-- outer -->
  <div class="card"><!-- middle -->
    <div class="card"><!-- inner -->
      Actual content here
    </div>
  </div>
</div>
```

**Why it's bad:** Each card layer adds padding, border, and border-radius. By
the third level, the content has been squeezed into a postage stamp and the page
looks like a Russian doll. AI models do this because they're composing from
components rather than layout. A designer thinks in spatial relationships; the
model thinks in nested `<div>` elements.

**The fix:** One container per content block. If you need visual grouping, use
a subtle background tint, a horizontal rule, or whitespace — not another card.

```html
<!-- GOOD — one container, whitespace for grouping -->
<section class="card">
  <h2>Section title</h2>
  <p>Content with breathing room.</p>
  <div class="subsection">
    <h3>Grouped by whitespace, not another card</h3>
  </div>
</section>
```

## 12. Section Slide

**The pattern:** A fade-and-slide-up entrance animation applied to every
section as the user scrolls, triggered by IntersectionObserver.

```css
/* BAD */
.section {
  opacity: 0;
  transform: translateY(24px);
  transition: opacity 0.6s ease, transform 0.6s ease;
}

.section.visible {
  opacity: 1;
  transform: translateY(0);
}
```

```js
// BAD — observer on every section
document.querySelectorAll('.section').forEach(section => {
  observer.observe(section);
});
```

**Why it's bad:** When every section animates on scroll, none of them feel
special. The user spends the entire scroll experience waiting for content to
finish animating. It adds perceived latency, creates motion fatigue, and
screams "I discovered IntersectionObserver and used it on everything."

**The fix:** Animate exactly one thing: the hero section, a single stat reveal,
or nothing at all. Most professional sites use zero scroll-triggered animations
beyond a subtle header transition.

```css
/* GOOD — no scroll animation, or at most one */
/* Content should be visible when the user scrolls to it */
```

## 13. Fake Sequence

**The pattern:** Numbered markers (01, 02, 03) applied to content that isn't
actually sequential — no step ordering, no dependency between items.

```html
<!-- BAD — these are features, not steps -->
<div class="features">
  <div class="feature"><span>01</span> Fast performance</div>
  <div class="feature"><span>02</span> Beautiful design</div>
  <div class="feature"><span>03</span> Easy integration</div>
</div>
```

**Why it's bad:** Numbers imply sequence. When the content isn't sequential
(features, values, capabilities), the numbers are lying to the reader. It's a
layout trick that prioritizes visual rhythm over semantic honesty. The reader's
brain processes "this is step 3 of 3" when it should be processing "this is a
feature."

**The fix:** If the content is sequential (a tutorial, a workflow), use numbers.
If it isn't (features, benefits, team members), use icons, color, or nothing.

```html
<!-- GOOD — no fake sequence, use icons or nothing -->
<div class="features">
  <div class="feature">
    <svg><!-- bolt icon --></svg>
    <strong>Fast performance</strong>
  </div>
</div>
```

## 14. Middle Dot Meta

**The pattern:** Meta information strings joined with middle dots:
"Author · Date · Category" or "A · B · C".

```html
<!-- BAD -->
<span class="meta">Jane Smith · 12 min read · Design</span>
```

**Why it's bad:** Middle dots are the AI's default meta separator. They appear
in almost every AI-generated blog card, article header, and content tile. The
problem isn't that middle dots are wrong — it's that using them everywhere,
without considering whether a comma, pipe, or line break would serve the
information better, signals "I didn't think about this."

**The fix:** Ask: does this metadata need to be on one line? If yes, consider a
pipe (`|`) or a simple comma. If the information is hierarchical, use line
breaks so each piece gets its own space.

```html
<!-- GOOD — considered, not defaulted -->
<div class="meta">
  <span class="meta-author">Jane Smith</span>
  <span class="meta-separator">·</span>
  <span class="meta-readtime">12 min read</span>
</div>
```

> Note: middle dots are fine when used intentionally. The anti-pattern is using
> them automatically on every meta string without thought.

## 15. Em Dash Label

**The pattern:** Labels formatted as `"WORD — fragment"` with a spaced em dash
connecting a category word to a descriptive fragment.

```html
<!-- BAD -->
<span class="label">DESIGN — How we think about systems</span>
<span class="label">ENGINEERING — Our approach to scale</span>
```

**Why it's bad:** The "CATEGORY — description" format is the AI's default blog
label pattern. It's almost never used in real design because it's redundant (the
category is usually obvious from context) and visually awkward with the wide
dash. It signals "this was auto-tagged."

**The fix:** If the label needs a description, write it as a sentence. If it
doesn't, drop the description entirely. A label should be one piece of
information, not two connected by punctuation.

```html
<!-- GOOD — label is the label, title is the title -->
<h2 class="section-title">How we think about systems</h2>
<p class="section-subtitle">A design engineering perspective</p>
```

## 16. Arrow Links

**The pattern:** Appending `→` (right arrow) to every link and button text to
signal "this is clickable."

```html
<!-- BAD -->
<a href="/about">Learn more →</a>
<a href="/pricing">View plans →</a>
<a href="/contact">Get in touch →</a>
<a href="/docs">Read the docs →</a>
```

**Why it's bad:** Arrows on links are the AI's way of saying "I don't trust the
design to communicate that this is interactive." When every link gets an arrow,
the arrow loses meaning. When every link has identical visual treatment, none
stand out. The arrow becomes visual noise that the reader filters out.

**The fix:** Links should look like links (color, underline, weight). CTAs
should look like buttons (background, padding, border-radius). If you need to
signal "this goes somewhere," add an arrow only to the primary CTA or to links
that navigate away from the current context.

```html
<!-- GOOD — one arrow, on the primary action, not every link -->
<a href="/about">Learn more</a>
<a href="/pricing" class="cta-primary">View plans →</a>
<a href="/contact">Get in touch</a>
```

## 17. Template Chrome

**The pattern:** The "eyebrow + heading + subtitle + CTA" stack that appears
identically on every section regardless of the content's needs.

```html
<!-- BAD — every section is identical -->
<section>
  <span class="eyebrow">FEATURES</span>
  <h2>Powerful features for modern teams</h2>
  <p class="subtitle">Everything you need to scale your workflow.</p>
  <a href="#" class="cta">Get started →</a>
</section>

<section>
  <span class="eyebrow">PRICING</span>
  <h2>Simple pricing for growing teams</h2>
  <p class="subtitle">Choose the plan that works for you.</p>
  <a href="#" class="cta">View plans →</a>
</section>
```

**Why it's bad:** This is the AI's default section template — every section gets
the same four-element stack regardless of what the content actually needs. Some
sections need a heading and body copy. Some need just an image. Some need
nothing but a list. The template-chrome approach ignores the content and
imposes a single structure on everything. It's the fastest way to make a page
feel like it was generated by looping over a JSON array.

**The fix:** Let each section determine its own structure. Some sections get a
heading and paragraph. Some get a grid of cards. Some get a single stat. Vary
the rhythm.

```html
<!-- GOOD — each section has the structure its content needs -->
<section class="hero">
  <h1>The one thing this product does</h1>
</section>

<section class="features">
  <h2>Three things that matter</h2>
  <div class="feature-grid"><!-- cards --></div>
</section>

<section class="testimonial">
  <blockquote>"The only thing that matters."</blockquote>
  <cite>Actual Customer</cite>
</section>
```

## Detection Summary

| # | Anti-Pattern | Primary Signal |
|---|-------------|---------------|
| 1 | Default Inter | `font-family: Inter, system-ui...` |
| 2 | Accent Word | `<em>` or `<i>` inside `<h1>`–`<h3>` |
| 3 | ALL CAPS Labels | `text-transform: uppercase` + `letter-spacing` |
| 4 | Mono Data Labels | `font-family: ...monospace` on non-code text |
| 5 | Tracked Out | `letter-spacing` > 0.1em |
| 6 | Purple Gradient | `linear-gradient` with #7C3AED/#4F46E5 range |
| 7 | Cream Default | Background #F4F1EA/#FAF7F2 range |
| 8 | Terracotta Accent | Accent #D97757/#C46A4A + cream background |
| 9 | Uniform Radius | Same `border-radius` on 3+ different element types |
| 10 | Clone Shadows | Same `box-shadow` on 3+ cards |
| 11 | Card Nesting | `.card` > `.card` > `.card` in HTML |
| 12 | Section Slide | IntersectionObserver on every section |
| 13 | Fake Sequence | Numbered markers on non-sequential content |
| 14 | Middle Dot Meta | `·` separator in meta strings |
| 15 | Em Dash Label | `"WORD — fragment"` pattern |
| 16 | Arrow Links | `→` on 3+ links/buttons |
| 17 | Template Chrome | Identical eyebrow+heading+subtitle+CTA on 3+ sections |

Each anti-pattern is individually detectable with CSS selector analysis and HTML
structure inspection. Combined, they form a "design taste" score that correlates
strongly with AI-generated output.
